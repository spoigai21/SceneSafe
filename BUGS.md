# BUGS — what broke, and what caught it

| # | Phase | What broke | What caught it | Fix |
|---|---|---|---|---|
| 1 | 0 | The MPS model rate kept rising from run to run (185 → 233 → 288 fps). One warm-up batch was not enough, so the first runs were timing GPU warm-up rather than steady state. | The timed runs climbed steadily instead of scattering around a mean. | The warm-up is now one full untimed pass over all batches. The later runs scatter at 206–255 fps with no trend. |
| 2 | 1 | The corpus download aborted entirely when the Internet Archive returned HTTP 500/504 for one title. One exception in the thread pool stopped every download. | The background download exited with code 1 partway through. | Each title now fails independently. curl retries server errors (`--retry-all-errors`, 15 s delay), resumes partial files, and the script lists the failed titles at the end. Re-running resumes the download. |
| 3 | 1 | Python HTTPS requests to archive.org failed certificate verification, although `curl` worked. Something on the network path re-signs TLS certificates, and Python checks against its own bundle rather than the OS store. | `CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain` when building the manifest. | Use `truststore`, which makes Python verify against the macOS certificate store. Verification was never switched off. |
| 4 | 2 | ONNX Runtime's int8 pre-processing step crashed (`AssertionError` in symbolic shape inference on one of CLIP's Reshape nodes). | The first Phase 2 run stopped with a traceback while building the int8 model. | Skip the optional symbolic shape inference (`skip_symbolic_shape=True`). The standard ONNX shape inference still runs. |
| 5 | 2 | Calibration titles for int8 were chosen by "file exists", not "file complete". One title (`cco_thegunandthepulpit`) was still downloading when it was picked. | Reviewing the calibration title list against the download log afterwards. | `corpus.is_downloaded()` now checks the byte size against the manifest. Impact: none measured. All 7 × 48 = 336 calibration frames decoded, and the static int8 model was rejected on accuracy anyway. |
| 6 | 2 | Core ML ran most of the model on the CPU and got slow (29–129 fps) when the ONNX file had a flexible batch size. It rejects operations with unbounded dimensions. | The first Core ML probe logged "unbounded dimension which is not supported" errors and showed low frame rates. | Export a fixed-batch ONNX file per batch size for Core ML (`clip_vitb32_visual_fp32_b<N>.onnx`). |
| 7 | 3 | The Phase 3 script aborted on start: `OMP: Error #15 ... libomp.dylib already initialized`. PyTorch and FAISS each bundle their own OpenMP runtime, and loading both in one process aborts. | The first run crashed before printing anything. | Embed the text queries in a separate process (cached in `data/phase3/`) so torch and faiss never load together. The model name moved to `scenesafe/embed/model.py` and the result helpers to `scenesafe/index/ranking.py`, so neither needs torch or faiss. The FAISS unit test runs in a child process, because pytest loads every test module into one process. The suggested `KMP_DUPLICATE_LIB_OK=TRUE` override was not used, because it is documented as able to give silently wrong results. |
| 8 | 4 | Labelling strips for scenes that run to the end of a film showed 1–2 blank frames: the evenly spaced sample times could fall after the last decodable frame, and nothing was pasted. | The second labeller reported a white frame next to an end card. | Sample times are clamped to the scene's last sampled second. The strips already labelled were not regenerated (every method's scenes were shown the same way); noted under Deviations in `results/phase4/SUMMARY.md`. |
| 9 | 6 | The scene-card model (Qwen3-VL-4B, mlx-vlm) would not run on the laptop CPU, so the VLM stages have no CPU lane. With MLX's default device set to the CPU, mlx-vlm first stopped with `KeyError: 'max_recommended_working_set_size'` (its GPU memory-limit helper). With that helper bypassed, generation failed with `[METAL] Command buffer execution failed: Caused GPU Timeout Error`: part of the model still ran on the GPU. | Probing the CPU lane before the Phase 6 timing runs. | Not fixed. Phase 6 reports the CPU lane for decode, CLIP and Whisper only (mlx-whisper does run on the CPU device), and says the VLM stages were not measured on the CPU. |
